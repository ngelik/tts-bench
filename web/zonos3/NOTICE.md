# ZONOS3-Mini browser runtime notice

This directory contains the official Zyphra browser-server source at commit
[`a50e14117d99181ba7f28047b451ba03ba1a09a9`](https://github.com/Zyphra/ZONOS3-Mini/tree/a50e14117d99181ba7f28047b451ba03ba1a09a9/servers/web),
licensed under MIT. The unmodified upstream `LICENSE` and `NOTICE` files are
retained under `upstream/`. The model weights and voice assets have separate
Apache-2.0 terms and are not covered by the source license.

The upstream notice describes the full ZONOS3 repository. This checkout bundles
the browser server, its model registries, the browser WAV helper and the pinned
API schema; it does not bundle the upstream SGLang, Python text-normalization,
speech-edit, aligner or MLX runtimes. The audio.cpp browser port and its
third-party notices are kept separately under `web/zonos3-cpu/` and in its
release assets.

The readable runtime bundles under `runtime/` are generated from
`upstream/servers/web/src/client.ts` with the pinned Vite 8.3.5 dependency and
the repository's `tools/build-zonos3-runtime.mjs` script. The build uses
`minify: false`. `runtime/BUILD-MANIFEST.json` records the upstream revision,
builder version, output paths, byte lengths and SHA-256 digests. Rebuild with
`npm run zonos3:runtime:build`; CI verifies that generated bytes match the
committed outputs.

The local integration changes are limited to:

- Filtering the preset voice catalog to the explicitly configured Imogen ID
  before fetching reference codes and embedding data; the benchmark disables
  unused preview-audio fetch/decode.
- Exporting a disposal method that terminates both upstream browser workers
  and resets their initialization state for the benchmark lifecycle.
- Reporting the adapter chosen by the actual inference worker, rejecting
  software/fallback adapters, and marking unavailable WebGPU on that runtime
  path with a specific unsupported reason.
- Installing a temporary `GPUComputePassEncoder` dispatch counter in the
  inference worker only for a separate request carrying
  `x-benchmark-dispatch-probe: 1`; restoring its original methods when that
  request ends and returning the count through the worker protocol.
- Requiring EOS for benchmark generation and carrying failures after response
  streaming begins through the worker terminal message and readable-stream
  error, so partial output is not accepted as a completed utterance.
- Forwarding fatal inference-worker, codec-worker and WebGPU device errors to
  active request streams.

No model inference kernels, tokenizer, text processing, or codec arithmetic are
changed by this integration. The benchmark sends canonical text spans without
additional normalization or splitting.
