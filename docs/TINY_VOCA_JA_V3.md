# Tiny Voca Japanese v3 F2

The `tiny-voca-ja-v3` profile pins the original 24 kHz FP32 ONNX graph at
Hugging Face revision `9b2305c81b9ca92ef8347eba473ea096c86f55c4` and upstream
frontend source at commit `49632c552d54a13664c1beb96904bef0154fbfc3`. It benchmarks
only voice F2 (index 0), speed 1, pitch shift 0 and pitch range 1. The model
bundles F2 and M2. The graph takes `tokens`, `stress`, `voice`, `speed`,
`pitch_shift` and `pitch_range`; it returns `audio` and `durations`. Output
length must equal duration frames times hop 256. The worker applies the upstream
whole-span 0.99 peak cap after joining the source span's utterances.

## Frontends and fixtures

Japanese uses upstream `oj_frontend.py` with pyopenjtalk-plus 0.4.1.post10
`g2p_prosody`, including its default Nani prediction fallback, and the original
OpenJTalk dictionary bytes bundled in the pinned Pyodide wheel. It uses the
three qualified Pyodide frontend wheels; it does not inject the Tsukuyomi-chan
dictionary overlay. The pinned `ja-article-v1` oracle is 38 source spans and 280
utterances, maximum 192 tokens, with one `<unk>` at source span 5.

English uses the upstream `text.py` normalization, punctuation parsing, token
mapping and stress logic with eSpeak NG 1.52.0 `en-us`. A small worker-local
callback sends normalized text pieces to the quiet eSpeak binding and returns
its raw IPA trace to the upstream Python parser/tokenizer. The three Emscripten
runtime assets are size/SHA-256 pinned in `assets.lock.json`; the native CLI
trace and fixture oracle are exact across 93 spans and 266 utterances, maximum
170 tokens.

The released metadata fingerprint `oj-en-1` is recorded as a release identity.
This adapter implements public frontend source and does not claim to reproduce
unavailable training annotation scripts. The Japanese and English fixture
oracles are separate. CPU/WASM and WebGPU/WASM both use the original graph and
ONNX Runtime Web 1.31.1; GPU capability is returned only after the untimed
synthesis probe observes actual WebGPU dispatch.

## Assets and diagnostics

All graph, runtime, frontend and notice assets are pinned in `assets.lock.json`.
The eSpeak ESM/WASM/data bundle is generated by
`tools/tiny-voca-ja-v3-espeak/build.sh` from its pinned source/toolchain and
must match the locked hashes. A clean asset cache can reuse the verified Japanese
Pyodide wheel outputs from `tools/build-tiny-voca-ja-wheels.sh`, then fetch the
other pinned assets:

```sh
bash tools/build-tiny-voca-ja-wheels.sh
bash tools/tiny-voca-ja-v3-espeak/build.sh
src=.cache/public/models/tiny-voca-ja-tsukuyomi-chan/7ed75cc5f521cc6be4cb57689b2c038928259ae9/66ee00d2c8cd61b34be1cde5880bac0e45b89fcf
rev=.cache/public/models/tiny-voca-ja-v3/9b2305c81b9ca92ef8347eba473ea096c86f55c4/49632c552d54a13664c1beb96904bef0154fbfc3
printf '%s  %s\n' '4da69e49c0b459728b41a7947a3ead7f98e2d5e7a44561080900ceaae967172b' "$src/pyopenjtalk_plus-0.4.1.post10-cp314-cp314-pyemscripten_2026_0_wasm32.whl" 'ad3ea354f3714b76d9773bb49e1c6e7a4dcfbf0fbf628090bc03c9420cc2cd34' "$src/sudachipy-0.7.0-cp310-abi3-pyemscripten_2026_0_wasm32.whl" | shasum -a 256 --check
mkdir -p "$rev"
install -m 644 "$src/pyopenjtalk_plus-0.4.1.post10-cp314-cp314-pyemscripten_2026_0_wasm32.whl" "$rev/"
install -m 644 "$src/sudachipy-0.7.0-cp310-abi3-pyemscripten_2026_0_wasm32.whl" "$rev/"
npm run assets -- fetch --model tiny-voca-ja-v3
npm run assets -- verify --model tiny-voca-ja-v3
```

Japanese initialization loads Pyodide plus its
G2P wheels. English initialization loads Pyodide stdlib and eSpeak only; it
does not load the Japanese wheels or import the Japanese phonemizer.
